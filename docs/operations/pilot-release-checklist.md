# Pilot Release Checklist v0.1

Use one copy of [the evidence template](templates/pilot-release-evidence-template.md) per exact candidate. Record safe identifiers and links, UTC times, operator and independent reviewer. The [deployment](deployment-runbook-v0.1.md), [backup/restore](backup-restore-runbook-v0.1.md), and [support](support-runbook-v0.1.md) runbooks supply the execution steps. A candidate is **FAIL / NOT READY** if any required item is unchecked, fails, or lacks an evidence reference. `N/A` is allowed only with an approved contract citation showing true non-applicability and reviewer sign-off.

## Per-candidate execution order

1. **Identity and provenance:** record the immutable 40-character commit SHA, application version, artifact filename, manifest SHA/version, ZIP SHA-256 and independent checksum verification. A dirty-worktree build is not an exact release candidate.
2. **CI and regression:** record GitHub Actions URL/run ID, status and backend/frontend jobs; run `dotnet restore SimpleStore.sln`, `dotnet build SimpleStore.sln --configuration Release --no-restore`, `dotnet test SimpleStore.sln --configuration Release --no-build`, `pnpm install --frozen-lockfile`, `pnpm --dir src/frontend/simplestore-web build`, and `pnpm --dir src/frontend/simplestore-web test`. Record test counts, errors/warnings and UTC evidence. CI alone does not replace real E2E or environment exercises.
3. **Database:** capture before/after migration identifiers with `Get-MigrationState.ps1`; identify reviewed migration bundle, clean install/current upgrade and data-preservation evidence where relevant. No implicit startup migration. Confirm backup/recovery decision before schema changes.
4. **Critical real E2E:** run the reviewed real Playwright scripts/specs on an isolated SQL Server/LocalDB test database. Record exact command, environment, DB identifier, candidate SHA, cases/result and cleanup. Cover PR-A, Slice 6, Sale completion/reprint, Return/Void, End-of-day and Today/C14. A DOM/PDF test is not physical printer certification.
5. **Backup readiness:** record FULL recovery, nightly Full/15-minute Log freshness, protected usable chain, restore proof and unresolved D-090/PR-B evidence. Link the operation/restore records rather than copying secrets.
6. **Windows/IIS deployment:** install the exact checked artifact using explicit migration and the [deployment runbook](deployment-runbook-v0.1.md). Record target Windows/IIS/site/app pool, install result, `/api/system/version` SHA/version/startup-log match, `/health/live`, `/health/ready`, authenticated read-only Store/Product/session smoke, JSON trace/log sample and before/after migration. Pilot infrastructure differences from Windows 11 must be identified.
7. **Printer:** if receipt/printing changed, record a candidate print sanity result and link the approved [80 mm physical certification](printer-certification-v0.1.md). If certification is pending, the candidate release gate fails.
8. **Recovery:** identify exact prior artifact, schema compatibility decision, reviewed `Switch-SimpleStoreRelease.ps1` gate or verified DB restore/forward fix, operator, recovery rehearsal and post-recovery health/version/smoke. Never assume application rollback reverses a migration.
9. **Review and decision:** list every open gap, operator/reviewer and UTC timestamps. Reviewer checks each item against actual evidence and records **PASS** only if every required item is evidenced. Product Owner review/approval of PR-C and the final M7 gate remain separate.

## D-094 deferred PR-B evidence: keep visible

Record each item as evidenced or `PENDING — D-094`: genuinely separate failure-domain backup storage; protected off-host/external copy; backup failure/freshness alert delivery; pilot retention behavior; backup-service SQL privilege review (including `CREATE DATABASE` for `RESTORE VERIFYONLY`); another-human-operator deployment/backup/support runbook exercise; and materially different pilot Windows Server/certificate/network/deployment evidence. D-090 still requires FULL recovery, nightly Full, 15-minute Log, usable 14-day chain, eight weekly Fulls, separate restricted failure domain and actual restore proof. C: and D: on one physical disk do not satisfy that requirement.

D-094 allows PR-C implementation while PR-B remains pending. It does not turn a pending PR-B item into a pass or authorize final Pilot Readiness/M7. PR-B and PR-C require separate Product Owner review/approval before the final M7 decision. PR-BLOCKER-03/04/05 and PR-BLOCKER-06/07 stay OPEN until their own reviewed closure evidence.
